# M6 设计文档：固定模式（Pinned Surface）+ Dock 系统占位

**日期**：2026-04-23  
**状态**：待实现  
**里程碑**：M6

---

## 1. 目标

M6 解决两个独立问题：

1. **Dock 系统占位**：最大化窗口自动避开 Dock 44px，关闭按钮不再被遮挡
2. **Panel 固定模式**：Panel 常驻显示，不因鼠标移出自动收起，支持拖拽改宽

这两个问题解耦实现，不互相依赖。

---

## 2. 状态模型

### 2.1 两条正交状态

```typescript
dockMode: 'floating' | 'occupied'
panelMode: 'hover' | 'pinned'
```

**`dockMode`**：
- `floating`：Dock 是普通置顶浮层，不影响系统工作区
- `occupied`：Dock 已注册 AppBar，最大化窗口自动避让 44px

**`panelMode`**：
- `hover`：Panel 悬停模式，鼠标移出后自动收起
- `pinned`：Panel 固定模式，常驻显示，不自动收起

### 2.2 状态约束

- 两个状态完全正交，不互相推导
- `dockMode = occupied` 不代表 `panelMode = pinned`
- `panelMode = pinned` 不触发任何 Dock 占位变更
- `panelMode` 不跨应用重启持久化（每次启动默认 `hover`）
- `dockMode` 由用户在设置里手动开启，开发阶段默认 `floating`

### 2.3 配置变更

新增配置项：

```typescript
layout: {
  // 已有
  edge: 'left' | 'right';
  panelDefaultWidth: number;
  pinned: boolean;  // 废弃，由运行时 panelMode 替代，不再持久化
  // 新增
  dockOccupancyEnabled: boolean;  // 默认 false
}
```

`panelMode` 不写入配置，纯内存状态。

## 3. 几何职责

### 3.1 核心原则

- **Dock 是唯一参与系统占位的窗口**
- **Panel 永远不参与系统占位**，只锚定在 Dock 外侧
- **AppBar 模式下，Dock 位置来源是系统返回的 `dockRect`**，不再读 `workArea`
- **Panel 位置永远基于 `dockRect` 推导**，不自己读 `workArea`

### 3.2 几何函数

三个纯函数，无副作用：

```typescript
// 现有，floating 模式继续用
getDockFloatingBounds(edge: Edge): Rectangle

// 新增，Panel 专用，基于 Dock 实际矩形
getPanelBoundsFromDockRect(
  edge: Edge,
  dockRect: Rectangle,
  panelWidth: number
): Rectangle

// 新增，PanelAnimationWindow 与 PanelWindow 同宽同位
getAnimationBoundsFromDockRect(
  edge: Edge,
  dockRect: Rectangle,
  panelWidth: number
): Rectangle  // 与 getPanelBoundsFromDockRect 返回值相同
```

`registerDockAppBar` 是有副作用的系统调用，放在 `DockOccupancyService` 里，不是纯函数。

### 3.3 "双扣 44px"陷阱

AppBar 注册成功后，Windows 会自动缩小 `workArea`。如果此时再用 `workArea` 算 Dock 位置，会拿到已扣掉 44px 的值，导致 Dock 往内缩、留出空隙。

**规则**：`registerDockAppBar` 成功后，Dock 位置只用 `ABM_SETPOS` 返回的 `rc`，不再读任何 Electron bounds API。这个 `rc` 缓存在 `DockOccupancyService` 里，供 Panel 锚定使用。

## 4. DockOccupancyService

### 4.1 职责

```typescript
class DockOccupancyService {
  registerDockAppBar(edge: Edge): Rectangle   // 返回系统协商后的 dockRect
  unregisterDockAppBar(): void
  startPositionWatcher(): void                // 每 3s 轮询，任务栏变化时重协商
  stopPositionWatcher(): void
  getCachedDockRect(): Rectangle | null       // 返回最后一次协商结果
}
```

### 4.2 注册流程

```
1. 构造 APPBARDATA，hWnd = Dock 窗口 HWND
2. SHAppBarMessage(ABM_NEW, &abd)
3. 设置 uEdge = ABE_RIGHT（或 LEFT）
4. 设置 abd.rc = display.bounds 对应边缘的矩形（不用 workArea）
5. SHAppBarMessage(ABM_QUERYPOS, &abd)   // 系统可能调整 rc
6. SHAppBarMessage(ABM_SETPOS, &abd)     // 提交最终位置
7. 缓存 abd.rc 为 dockRect
8. 返回 dockRect
```

**关键**：步骤 4 用 `display.bounds`，不用 `workArea`。步骤 5-6 必须顺序执行，不能跳过 `ABM_QUERYPOS`。

### 4.3 HWND 获取

```typescript
const hwndBuffer = dockWindow.getNativeWindowHandle();
const hwnd = hwndBuffer.readBigUInt64LE(0);  // Windows x64
```

### 4.4 失败降级

`registerDockAppBar` 失败时：
- `dockMode` 回退到 `floating`
- Dock 继续正常显示
- 不崩溃，不影响其他功能
- 日志记录 ERROR

### 4.5 watcher

- `registerDockAppBar` 成功后立即 `startPositionWatcher()`
- `unregisterDockAppBar()` 时必须 `stopPositionWatcher()`
- watcher 每 3s 轮询一次
- 发现几何变化时重新走 `ABM_QUERYPOS + ABM_SETPOS`，更新缓存 `dockRect`
- 需要 debounce 或 token 防止并发重协商导致抖动

## 5. Panel 固定模式

### 5.1 pin/unpin

**`hover → pinned`**（点击 📌）：
1. `panelMode = pinned`
2. 取消所有自动收起计时器
3. 显示拖拽句柄
4. 保持当前 Panel 可见
5. 不触发任何 Dock 占位变更

**`pinned → hover`**（再次点击 📌）：
1. `panelMode = hover`
2. 隐藏拖拽句柄
3. 当前 Panel 执行正常收起动画
4. 恢复 hover-open / hover-close 逻辑
5. Dock 占位不变

### 5.2 固定态切图标

`panelMode = pinned` 时：
- 鼠标移入或点击其他图标 → 直接 `switchPanel(nextId)`，不触发收起动画
- 保持 `panelMode = pinned`，拖拽句柄保持可见
- 切图标时 Panel 宽度保持当前用户调整后的宽度，不跳回 `preferredWidth`
- 切到 `+`、`edit-site`、`site-info` 等内置面板也保持 `pinned`

### 5.3 拖拽改宽

只在 `panelMode = pinned` 时启用。

**渲染进程（`ResizeHandle`）**：
- `mousedown`：记录 `startX`、`startWidth`
- `mousemove`：只改 CSS 宽度，不发 IPC
- `mouseup`：发送 `panel:commit-resize(finalWidth)`

**主进程（`panelHandlers`）**：
收到 `panel:commit-resize` 后，用当前 `dockRect`（来自 `DockOccupancyService.getCachedDockRect()`，floating 模式下用 `getDockFloatingBounds`）计算新 Panel 位置，然后**同步**执行：

```typescript
const panelRect = getPanelBoundsFromDockRect(edge, dockRect, finalWidth);
panelWindow.setBounds(panelRect);
panelAnimationWindow.setBounds(panelRect);
const view = webPanelHost.getView(currentPanelId);
if (view) view.setBounds(contentRect);
configStore.update({ layout: { panelDefaultWidth: finalWidth } });
```

三处 `setBounds` 必须同步提交，不能有 await 打断。

**宽度约束**：最小 320px，最大 `display.workArea.width × 0.5`。

## 6. 事件流

### 6.1 应用启动

1. 读取配置
2. `panelMode = hover`（不从配置恢复）
3. 若 `config.layout.dockOccupancyEnabled = true`：
   - `registerDockAppBar(edge)` → 得到 `dockRect`
   - 成功：`dockMode = occupied`，`DockWindow.setBounds(dockRect)`，`startPositionWatcher()`
   - 失败：`dockMode = floating`，日志 ERROR，继续正常启动
4. 若 `dockOccupancyEnabled = false`：`dockMode = floating`
5. Panel 初始隐藏

### 6.2 左右贴边切换

1. 记住当前 `panelMode`
2. 若 `panelMode = pinned`，先隐藏 Panel
3. 若 `dockMode = occupied`：`unregisterDockAppBar()`，`stopPositionWatcher()`
4. 更新 `edge`
5. 若 `dockMode = occupied`：`registerDockAppBar(newEdge)` → 新 `dockRect`，`startPositionWatcher()`
6. `DockWindow.setBounds(dockRect)`
7. 若之前 `panelMode = pinned`：用新 `dockRect` 重算 Panel，重新显示，保持 `pinned`
8. 若之前 `panelMode = hover`：Panel 维持隐藏

### 6.3 隐藏到托盘

1. 隐藏 Panel
2. 若 `dockMode = occupied`：`unregisterDockAppBar()`，`stopPositionWatcher()`
3. 隐藏 Dock
4. 保留 `panelMode` 内存态（不强制降级）

### 6.4 从托盘恢复

1. 若 `dockOccupancyEnabled`：`registerDockAppBar(edge)` → `dockRect`，`startPositionWatcher()`
2. `DockWindow.setBounds(dockRect)`，显示 Dock
3. 若 `panelMode = pinned` 且有 `activePanel`：用 `dockRect` 计算 Panel，显示 Panel
4. 若 `panelMode = hover`：Panel 维持隐藏

### 6.5 进入全屏

1. 隐藏 Panel
2. 若 `dockMode = occupied`：`unregisterDockAppBar()`，`stopPositionWatcher()`
3. 隐藏 Dock
4. **强制 `panelMode = hover`**（不保留 pinned）

### 6.6 退出全屏

1. 若 `dockOccupancyEnabled`：`registerDockAppBar(edge)` → `dockRect`，`startPositionWatcher()`
2. `DockWindow.setBounds(dockRect)`，显示 Dock
3. `panelMode` 保持 `hover`，Panel 不自动恢复

### 6.7 watcher 触发重协商

1. 重新 `ABM_QUERYPOS + ABM_SETPOS`，得到新 `dockRect`
2. `DockWindow.setBounds(dockRect)`
3. 若 `panelMode = pinned`：重算并更新 `PanelWindow`、`PanelAnimationWindow`、当前 `WebContentsView`

## 7. 实现顺序

严格按阶段推进，每阶段验收通过才进入下一阶段。

### 阶段 1：状态字段与纯函数（无系统调用）

- 新增 `dockMode` / `panelMode` 内存状态
- 新增 `getDockFloatingBounds`、`getPanelBoundsFromDockRect`
- 新增配置项 `dockOccupancyEnabled`（默认 false）
- 不接任何 AppBar 逻辑

### 阶段 2：koffi 原型验证（独立，不接 UI）

- 只验证 koffi 加载 + `SHAppBarMessage` 调用
- 开发模式下临时按钮触发：注册右侧占位 → 最大化窗口关闭按钮不被挡 → 释放占位
- **不接 `DockOccupancyService`，不接 `PanelManager`**
- 这一步不稳，后面全部暂停

### 阶段 3：DockOccupancyService + 占位开关

- 封装 `DockOccupancyService`
- 设置里加"启用 Dock 占位模式（实验性）"开关
- 接入启动流程

验收：
- 开启开关后最大化窗口关闭按钮可点击（左右贴边都成立）
- 隐藏到托盘释放占位，恢复重新注册
- watcher 能纠正任务栏位置变化

### 阶段 4：Panel pinned

- `📌` 切换 `panelMode`
- 固定态不自动收起
- 固定态切图标不退出 pinned
- 固定态切内置面板不退出 pinned

验收：
- 连续切 5 个站点不掉回 hover
- 打开添加/编辑/站点信息面板保持 pinned

### 阶段 5：固定态拖拽改宽

- 显示拖拽句柄
- mousemove 只改 CSS
- mouseup 同步提交三处 setBounds
- 持久化 `panelDefaultWidth`

验收：
- 拖宽平滑，提交后无错位
- 拖宽后切图标不跳宽

### 阶段 6：边界事件联动

- `switchEdge`
- `hideToTray` / `showFromTray`
- `enterFullscreen` / `exitFullscreen`
- `display-metrics-changed`

## 8. 风险点

| 风险 | 级别 | 缓解 |
|---|---|---|
| koffi FFI 调用 `SHAppBarMessage` 参数错误 | 极高 | 阶段 2 独立原型先验证，不接 UI |
| `workArea` 和 `dockRect` 混用导致留缝 | 高 | AppBar 注册后只用缓存 `dockRect`，`getDockFloatingBounds` 只在 floating 模式用 |
| 全屏隐藏顺序错误（先 hide 再 unregister） | 高 | 严格按：unregister → hide Dock |
| `commitResize` 三处 setBounds 不同步 | 中 | 同一事件循环内顺序执行，无 await |
| watcher 并发重协商导致抖动 | 中 | debounce 或 token 保护 |

## 9. 必须手测的场景

不适合只靠自动化：

- 最大化窗口右上角按钮是否能点击
- 任务栏在底部/左侧/右侧时 Dock 是否仍贴边正确
- 左右贴边切换后是否留缝
- `hideToTray` 后是否真的释放占位（用 Spy++ 或观察最大化窗口行为）
- 固定态拖宽后切图标是否保持当前宽度
- 全屏进入退出后是否正确降回 hover

---

## 10. 停下来重想的信号

出现以下任一情况，暂停，不继续堆修复：

- Dock occupied 原型仍出现留缝或双扣宽度
- tray 隐藏后占位不能稳定释放
- 固定态切图标仍反复掉回 hover
- 拖宽时三层窗口无法同步
- watcher 导致重复注册或位置抖动
