## 2. 状态模型

### 2.1 `panelMode`

```ts
// PanelManager 私有字段
private panelMode: 'hover' | 'pinned' = 'hover';
```

- 纯内存态，不写配置
- 每次应用启动回 `hover`
- 托盘隐藏 / 全屏不重置（同会话内保留）
- 切换贴边方向（M7 实现时）先切回 `hover`

### 2.2 与 `sticky` 的关系

M5 已有 `sticky`（点击面板后 hover-close 不触发的单次粘性）。保留，语义不变。

优先级：`sticky || panelMode === 'pinned'` → 跳过 hover-close。两者独立存在，`panelMode` 切回 `hover` 时不影响 `sticky`。

### 2.3 配置变更（删字段）

PRD §4 `AppConfig.layout.pinned` 字段删除。已同步改 PRD。

`ConfigStore` 迁移：读配置时若 `layout.pinned` 存在则丢弃。默认配置 `constants.ts` 移除该字段。

## 3. UI 变更

### 3.1 📌 按钮

`renderer/panel-chrome/App.tsx` 已有 PinOff 占位（line 576-581）。补：

- 根据 `chromeState.panelMode` 切图标：`hover` → `PinOff`；`pinned` → `Pin`
- tooltip：`hover` 显示"固定侧窗格"，`pinned` 显示"取消固定侧窗格"
- `onClick` → `window.panelAPI.togglePin()`

### 3.2 ResizeHandle

新建 `renderer/panel-chrome/components/ResizeHandle.tsx`，完全照抄 PRD §5.14 场景 D 代码模板。

- 仅当 `panelMode === 'pinned'` 时挂载（unmount 时移除事件监听）
- 位置：panel 内侧 4px 绝对定位
  - `edge='right'`：`left: 0; top: 0; bottom: 0; width: 4px`
  - `edge='left'`：`right: 0; top: 0; bottom: 0; width: 4px`
- `cursor: ew-resize`
- mousemove：只改 `.panel-chrome` 的 `style.width`
- mouseup：`window.panelAPI.commitResize(finalW)`

Clamp 在渲染进程也做一次（`[320, screen.availWidth × 0.5]`），主进程收到后再 clamp 一次兜底。

## 4. IPC 合约变更

### 4.1 `panel:toggle-pin`（新增）

- R→M invoke
- 无参
- 响应：`IpcResult<void>`
- 主进程：翻 `panelMode`；若切到 `hover` 且当前 open → 走 `hidePanel()` 收起动画；推 `panel:state`

### 4.2 `panel:commit-resize`（新增）

- R→M invoke
- 参数：`newWidth: number`
- 响应：`IpcResult<void>`
- 主进程：`PanelManager.commitResize(width)`

### 4.3 `panel:state`（改字段）

旧：`{ activePanelId, panelVisible, pinned, edge }`
新：`{ activePanelId, panelVisible, panelMode, edge }`

渲染进程所有读 `panel:state.pinned` 的地方同步改。

## 5. 主进程逻辑

### 5.1 `PanelManager.togglePin`

```ts
async togglePin(): Promise<void> {
  if (this.panelMode === 'hover') {
    this.panelMode = 'pinned';
    this.cancelCloseTimer();   // 现有 this.closeTimer 清除
    this.emitState(...);
    return;
  }
  // pinned → hover
  this.panelMode = 'hover';
  this.emitState(...);
  if (this.state === 'open') {
    await this.hidePanel(false);
  }
}
```

### 5.2 `PanelManager.commitResize`

```ts
commitResize(newWidth: number): void {
  const display = screen.getDisplayNearestPoint(screen.getCursorScreenPoint());
  const min = 320;
  const max = Math.floor(display.workArea.width * 0.5);
  const width = Math.min(Math.max(newWidth, min), max);

  this.panelWindow.updateBounds(this.edge, width);
  this.animationWindow.updateBounds(this.edge, width);  // 一次性同步，无害

  const view = this.webPanelHost.getView(this.currentPanelId);
  if (view) {
    const [w, h] = this.panelWindowRef.getContentSize();
    view.setBounds({ x: 0, y: CHROME_HEIGHT, width: w, height: h - CHROME_HEIGHT });
  }

  this.configStore.update({ layout: { panelDefaultWidth: width } });
}
```

同一 tick 同步执行，无 `await`。符合 §5.14 铁律 2。

### 5.3 hover-close 门槛

现有 `PanelManager:416` 的 `if (this.sticky || this.pinned)` → 改为 `if (this.sticky || this.panelMode === 'pinned')`。

同样 `:159` 同步改。删除 `this.pinned` 字段和 `applyHoverConfig` 里相关读取。

### 5.4 切图标不退出 pinned

`switchPanel` 当前（`:344`）实现 view 热切，本身不触碰 `panelMode`。但 `:347` 有 `this.sticky = false` —— `pinned` 时不应 reset。改为：

```ts
if (this.panelMode === 'hover') {
  this.sticky = false;
}
```

（避免 pinned 下用户之前点过 panel 设的 sticky 被清掉——虽然 pinned 下 sticky 本无影响，行为一致即可）

### 5.5 打开内置面板保持 pinned

当前 `showPanel(buildBuiltinPanelId(...), true)` 带 `sticky = true`（`:287` / `:292`）。`panelMode` 与 `sticky` 正交，内置面板打开后：
- hover 态：sticky=true 保证不自动收起
- pinned 态：panelMode 仍是 pinned，`showPanel` 正常展示，无需特殊处理

## 6. 启动 / 托盘 / 全屏

**启动**：`panelMode = 'hover'`（字段默认值）。无特殊处理。

**托盘隐藏**：`PanelManager` 内存态保持，Dock/Panel 隐藏。恢复时 Dock 显示，Panel 不自动展开。用户下次 hover 图标走现有 `showPanel`，若内存 `panelMode` 仍是 `pinned` 则展示 pinned 态（📌 显示 Pin 图标、ResizeHandle 可见）。

**全屏**：同托盘，PRD §7.4 "隐藏 Dock 与 Panel"，`panelMode` 不变。

## 9. 风险

| 风险 | 级别 | 缓解 |
|---|---|---|
| ResizeHandle 位置放错侧（内/外侧混淆） | 低 | 代码注释明确"内侧=靠 Dock 那侧"；手测两种 edge |
| `commitResize` 触发 panel 闪烁 | 中 | 严格单 tick 同步；动画窗口同步 updateBounds 避免下次开合错位 |
| 老配置 migration 破坏其他字段 | 中 | migration 只删 `pinned` 键，其它字段原样透传；写单测 |
| panel-chrome 读 `panel:state.pinned` 有遗漏未迁移 | 中 | 全局搜 `state.pinned` / `pinned:` 逐一改 |

## 10. 停下来重想的信号

- 一次拖宽主进程日志超过 1 条 `setBounds` → 有地方在 mousemove 循环里提交
- 切图标后 📌 图标状态与 `panelMode` 不一致 → `panel:state` 推送链路有 bug
- migration 后老配置文件里仍残留 `pinned` 字段 → migration 没生效
