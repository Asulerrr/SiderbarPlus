# M8 设置面板设计

**目标**：实现 PRD §5.12 内置设置面板 + 主题系统扩展（system / light / dark / custom）。

**架构**：`builtin:settings` 作为 BuiltinWidgetId，通过现有 panel-chrome 渲染树的 `builtin.widgetId` 分支挂载 React `SettingsView`。配置变更经现有 `dockAPI.updateConfig` / 新增 `panelAPI.updateConfig`（无则补）通过 IPC 写 `ConfigStore`，main 进程在 `configHandlers` 检测 diff 并应用副作用（已有 autoLaunch / hideOnFullscreen / edge，新增 panelDefaultWidth / appearance / autoShowDock 启动期）。

---

## 1. 触发与生命周期

- 入口：QuickMenu 「设置」项（当前是 placeholder dialog）→ 改为通过新 IPC `app:open-settings` 调用 `windowManager.showPanel(BUILTIN_SETTINGS_ID, true)`，pinned 模式打开。
- 内置 widget：`'settings'` 加入 `BuiltinWidgetId` 联合类型；`buildBuiltinPanelId('settings')` 返回 `'builtin:settings'`（无 target）。
- 不出现在 dock 图标列表（同 add-site 现有规则）。
- 关闭 = 用户 × 或外部点击；状态不持久化（每次重新打开默认在「常规」分区）。

---

## 2. 配置 Schema 变更

`AppConfig` 新增 `appearance` 顶层段（与 `app` / `layout` / `behavior` 平级）：

```ts
appearance: {
  themeMode: 'system' | 'light' | 'dark' | 'custom';
  customColor: string;  // '#RRGGBBAA'（含 alpha），仅 custom 模式生效
}
```

`DEFAULT_CONFIG`：`{ themeMode: 'system', customColor: '#1B1B1BFF' }`。

`ConfigStore.update` 已有 `appearance: { ...current.appearance, ...patch.appearance }` 模式（参考 layout 合并逻辑），需在 update 方法里加同款分支。

---

## 3. UI 布局（panel-chrome 内部）

左导航 188px + 右内容自适应。导航项 5 个：常规 / 外观 / 行为 / 数据 / 关于。当前选中项高亮（accent 色边线）。

### 3.1 常规
- 开机自启：Toggle → `app.autoLaunch`
- 启动时显示侧边栏：Toggle → `app.autoShowDock`
- 全屏自动隐藏：Toggle → `app.hideOnFullscreen`

### 3.2 外观
- 图标栏位置：Radio（左 / 右）→ `layout.edge`
- 面板默认宽度：Slider 320–800 → `layout.panelDefaultWidth`
- **主题模式**：Radio（跟随系统 / 浅色 / 深色 / 自定义）→ `appearance.themeMode`
- **自定义颜色**：仅 themeMode='custom' 时显示。`<input type="color">` + 单独 alpha slider 0–100%。合成为 `#RRGGBBAA` 写 `appearance.customColor`。

### 3.3 行为
- 悬停触发延迟：Slider 100–500ms → `behavior.hoverOpenDelayMs`
- 离开关闭延迟：Slider 100–800ms → `behavior.hoverCloseDelayMs`
- 隐藏时继续播放音频：Toggle → `behavior.keepAudioOnHide`

### 3.4 数据
- 打开配置文件夹（按钮）→ IPC `settings:open-config-folder` → `shell.openPath(app.getPath('userData'))`
- 导出配置（按钮）→ IPC `settings:export-config` → `dialog.showSaveDialog` → 把当前 `config.json` **原样复制**到所选路径
- 导入配置（按钮）→ IPC `settings:import-config` → `dialog.showOpenDialog` → 校验 JSON.parse + 顶层字段存在 → `ConfigStore.update`(整个对象) → **重新加载窗口**（不重启进程）：`windowManager.reloadAfterImport()` 销毁所有窗口 + `createWindows` 重建（不退出 app）
- 清除所有 Cookie 和缓存（红色按钮）→ 二次确认 dialog → IPC `settings:clear-storage-data` → 遍历所有 `WebContentsView.session` 调 `clearStorageData()`

### 3.5 关于
- 应用名 + 版本（来自 `APP_NAME` / `APP_VERSION`）
- 检查更新（按钮）→ IPC `settings:check-update` → 返回 `{ status: 'placeholder' }`，UI 弹「M9 实现」对话框
- GitHub 仓库链接 → `shell.openExternal`
- 退出程序（按钮）→ IPC `settings:quit-app` → `app.quit()`

## 4. 主题系统

### 4.1 主题色解析

```
themeMode === 'system'  → main 读 nativeTheme.shouldUseDarkColors → dark/light 预设
themeMode === 'light'   → 固定浅色预设
themeMode === 'dark'    → 固定深色预设
themeMode === 'custom'  → 使用 customColor
```

预设（写在 `shared/theme.ts`）：
- `dark`:  `{ bg: '#1B1B1BFF', fg: '#FFFFFFE6' }`
- `light`: `{ bg: '#F5F5F5FF', fg: '#1B1B1BE6' }`

### 4.2 自定义色文字推导

`getReadableForeground(bgHex8)`：
- 解析 `#RRGGBBAA`，提取 RGB
- 计算相对亮度 `Y = 0.299R + 0.587G + 0.114B` (0–255)
- `Y > 128` → 黑字 `#1B1B1BE6`；否则白字 `#FFFFFFE6`
- alpha 不参与亮度计算（透明背景假设亮度低 → 白字优先；用户可在 dark 桌面下看清）

### 4.3 应用机制

CSS 变量注入到 dock root + panel-chrome root：
- `--surface-bg`
- `--surface-fg`

替换硬编码：
- `tailwind.config` 的 `colors.dock` → `'var(--surface-bg)'`
- panel-chrome inner card `bg-[#1b1b1b]` → 类名改为 `bg-[var(--surface-bg)]`

主进程 `ThemeService`：
- 启动时根据 themeMode 计算当前主题，发 `theme:updated` 事件给所有窗口
- 监听 `nativeTheme.on('updated')`，仅在 themeMode='system' 时重算并广播
- `configHandlers` 检测 `appearance` 变更时也调用 `themeService.refresh()`

### 4.4 透明窗口重建

DockWindow 当前 `transparent: false`。当 customColor 的 alpha < 255 或 themeMode 切换到 custom 时，需要 `transparent: true`。

策略：
- DockWindow / PanelWindow 在创建时根据 `needsTransparency(appearance)` 决定 `transparent` 与 `backgroundColor`
- `appearance` 变更后如果 `needsTransparency` 结果变化 → `WindowManager.recreateWindows()` 销毁全部窗口 + createWindows 重建
- 同一个 `transparent` 状态内调色不重建（仅刷 CSS 变量）

## 5. 副作用应用（main 进程响应配置变更）

`configHandlers.configUpdate` 现有 diff 检测扩展：

| 字段变化 | 副作用 |
|---|---|
| `app.autoLaunch` | autoLaunchService.sync（已有） |
| `app.hideOnFullscreen` | fullscreenWatcher.start/stop（已有） |
| `app.autoShowDock` | **仅持久化**，影响下次启动 bootstrap 是否调用 `dockWindow.show()` |
| `layout.edge` | windowManager.applyEdgeChange（已有） |
| `layout.displayId` | windowManager.applyEdgeChange（已有） |
| `layout.panelDefaultWidth` | **新增**：panelManager 当前打开的 panel 不响应；下次打开按新值；不立即重定位 |
| `behavior.hoverOpenDelayMs` | 无副作用（PanelManager 每次 hover 读最新 config） |
| `behavior.hoverCloseDelayMs` | 同上 |
| `behavior.keepAudioOnHide` | **新增**：PanelManager.hidePanel 在 hide 时根据该值调 `view.webContents.setAudioMuted(true/false)` |
| `appearance.themeMode` / `customColor` | **新增**：themeService.refresh + 必要时 recreateWindows |

`bootstrap` 修改：
- 当前 dockWindow 创建后即 showInactive。改为：仅当 `config.app.autoShowDock || !isAutoStart`（默认 autoShowDock=true 不影响），手动开机自启场景可不显示。
- 实际 `--autostart` 参数 + `autoShowDock=false` 时跳过 show，让 dock 留在托盘等待用户激活。
